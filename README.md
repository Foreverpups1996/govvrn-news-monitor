# Монитор новостей Воронежской области → Telegram

**Репозиторий:** https://github.com/Foreverpups1996/govvrn-news-monitor

Программа следит за новостями Воронежской области и отправляет **новые** новости
в личные сообщения Telegram-контакту `@IF_13TIKHONOVA`.

Источники (по приоритету):

1. **сайт <https://www.govvrn.ru/news/all>** — полный поток новостей. Сайт
   блокирует зарубежные дата-центры (включая раннеры GitHub Actions), поэтому
   скрипт сначала пробует открыть его напрямую, затем — через бесплатные
   российские прокси (список берётся из публичных источников, удачный прокси
   запоминается в `state.json`).
2. **официальный telegram-канал [@govvrn36](https://t.me/s/govvrn36)**
   (Правительство Воронежской области) — резервный источник, если сайт недоступен.
   Канал отстаёт от сайта в среднем на **~70 минут** и публикует примерно
   **20%** новостей сайта (это курированная подборка, а не полный поток).

Работает на GitHub Actions **каждые 15 минут**, поэтому работает, даже когда ваш
компьютер выключен.

Сообщение выглядит так (для сайта — ссылка на govvrn.ru, для канала — на пост):

```
📰 Заголовок новости
🕒 15.10.2026 14:53
🔗 Читать на govvrn.ru
```

## Быстрая настройка (пошагово)

### Шаг 1. Создайте бота

1. Откройте Telegram, найдите **@BotFather** и напишите ему `/newbot`.
2. Придумайте имя (например `VrnNewsBot`) и юзернейм (например `vrn_news_monitor_bot`).
3. BotFather пришлёт **токен** вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxx` —
   скопируйте и сохраните, он понадобится на шаге 4.

### Шаг 2. Контакт должен написать боту `/start`

> Бот может писать в личку только тому, кто сам с ним начал диалог.

Перешлите контакту `@IF_13TIKHONOVA` ссылку на вашего бота
(`https://t.me/ВАШ_ЮЗЕРНЕЙМ_БОТА`) и попросите написать ему:

```
/start
```

### Шаг 3. Узнайте chat_id

На своём компьютере (Python уже установлен) в папке проекта выполните:

```bat
set TELEGRAM_BOT_TOKEN=СЮДА_ВАШ_ТОКЕН
py news_monitor.py --find-chat
```

Вывод будет примерно таким:

```
chat_id=712345678 тип=private имя='...'
```

Число `712345678` — это **chat_id**, скопируйте его.

#### Если локально не получается (блокировка Telegram провайдером)

В России многие провайдеры блокируют `api.telegram.org` — тогда локальный запуск
падает с ошибкой вида `SSLError: UNEXPECTED_EOF_WHILE_READING`. **На саму программу
это не влияет**: GitHub Actions работает за границей, где блокировки нет.

Узнать chat_id в обход блокировки можно прямо на GitHub (после шагов 4–5, когда
секрет `TELEGRAM_BOT_TOKEN` уже добавлен):

1. Вкладка **Actions** → слева **«Найти chat_id»** → **Run workflow**.
2. Откройте завершившийся запуск и посмотрите лог шага
   «Показать chat_id всех, кто писал боту» — там будет строка `chat_id=...`.

Если есть VPN или прокси, можно и локально: укажите прокси в переменной
`TELEGRAM_PROXY` (например `socks5://127.0.0.1:1080`).

### Шаг 4. Создайте репозиторий и залейте файлы

1. Откройте <https://github.com/new>, создайте репозиторий
   (например `govvrn-news-monitor`), поставьте **Private** (секреты-токены
   не любят публичность), кнопки «Add README» не нужны.
2. Скопируйте папку проекта `F:\govvrn-news-monitor` в репозиторий и запушьте:

```bat
cd F:\govvrn-news-monitor
git init
git add .
git commit -m "Монитор новостей govvrn.ru"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/govvrn-news-monitor.git
git push -u origin main
```

### Шаг 5. Добавьте секреты

Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**,
создайте два секрета:

| Имя секрета           | Значение                          |
|-----------------------|-----------------------------------|
| `TELEGRAM_BOT_TOKEN`  | токен от BotFather (шаг 1)        |
| `TELEGRAM_CHAT_ID`    | числовой chat_id (шаг 3)          |

Необязательный секрет `TELEGRAM_PROXY` нужен только если GitHub по какой-то причине
не сможет достучаться до Telegram (обычно не требуется).

### Шаг 6. Включите workflow

Репозиторий → вкладка **Actions** → если она выключена, нажмите
«I understand my workflows, go ahead and enable them».

Готово! Теперь каждые 15 минут скрипт проверяет сайт и шлёт только новые новости.

Для проверки запустите вручную: **Actions → «Новости govvrn.ru → Telegram» →
Run workflow** (при первом запуске ничего не отправляется — все текущие новости
сразу помечаются как прочитанные, чтобы не спамить; отправить проверку можно
флагом `--send-latest 3`, см. ниже).

## Локальный запуск (для отладки)

```bat
cd F:\govvrn-news-monitor
py -m pip install -r requirements.txt

set TELEGRAM_BOT_TOKEN=токен
set TELEGRAM_CHAT_ID=чат_ид

py news_monitor.py --dry-run      # показать новые новости без отправки
py news_monitor.py --test         # отправить тестовое сообщение
py news_monitor.py --send-latest 3  # отправить 3 последние новости
py news_monitor.py                # обычный цикл: отправить новые, сохранить состояние
py news_monitor.py --source telegram --dry-run  # принудительно из канала @govvrn36
py news_monitor.py --source site --no-proxies   # только сайт, без перебора прокси
```

## Управление из GitHub (вкладка Actions)

| Workflow | Что делает |
|----------|------------|
| **Новости govvrn.ru → Telegram** | Основной. Идёт по расписанию каждые 15 минут. При ручном запуске можно указать `send_latest` — сколько свежих новостей отправить сразу. |
| **Найти chat_id** | Показывает chat_id всех, кто писал боту. Нужен один раз при настройке. |
| **Проверка отправки** | Отправляет получателю одно тестовое сообщение. Удобно, чтобы убедиться, что всё настроено верно. |

Порядок первого запуска:

1. Добавьте секреты (шаг 5).
2. **Actions → «Проверка отправки» → Run workflow** — получателю придёт тестовое
   сообщение. Если пришло — всё настроено правильно.
3. Если хотите сразу получить несколько свежих новостей (а не ждать следующей):
   **Actions → «Новости govvrn.ru → Telegram» → Run workflow**, в поле
   `send_latest` укажите, например, `3`.
   Сделайте это **до** первого автоматического запуска — иначе все текущие новости
   уже будут помечены как прочитанные, и «догон» ничего не отправит.
4. Дальше всё работает само: каждые 15 минут приходят только новые новости.

## Как это работает

- `news_monitor.py` получает новости:
  - **с сайта govvrn.ru** — напрямую, а если сайт недоступен (зарубежный
    дата-центр блокируется) — через бесплатные российские прокси. Прокси
    применяется **только** к запросам к сайту, к Telegram токен никогда не
    передаётся;
  - **из канала @govvrn36** — если сайт недоступен даже через прокси;
- Затем сравнивает новости со списком уже отправленного (`state.json`) и шлёт
  только новое, от старых к новым. Сетевые сбои и лимиты Telegram
  обрабатываются с повторами.
- `.github/workflows/news.yml` — запускает скрипт каждые 15 минут: перед работой
  подтягивает свежий `state.json`, после работы коммитит обновлённое состояние
  обратно в репозиторий (последним и всегда актуальным).
- Отправка — официальный Telegram Bot API, личные сообщения.
- В `state.json` рядом со списком отправленного может храниться подобранный
  прокси (`"proxy": "socks5h://..."`) — он пробуется первым в следующий раз.

## Важные замечания

- **Первый запуск ничего не шлёт** — только запоминает текущие новости.
  Проверить отправку: `py news_monitor.py --send-latest 3`.
- **Дубли невозможны**: каждый адрес новости хранится в `state.json`; у постов
  канала дополнительно учитывается ссылка на страницу сайта внутри поста, чтобы
  при смене источника одна и та же новость не ушла дважды.
- **Защита от одновременных запусков**: запуски сериализуются (concurrency), а
  перед работой скрипт подтягивает самый свежий `state.json` из репозитория
  (запуск мог ждать в очереди и стартовать со старой копией). При сохранении
  состояния списки отправленного объединяются, поэтому ни одна отметка не
  теряется.
- **Бесплатные прокси нестабильны.** Если рабочий прокси найден, он сохраняется и
  используется дальше; когда перестаёт работать — подбирается новый. Пока ни один
  прокси не подошёл, новости идут из telegram-канала (позже и не все — см. выше).
- **GitHub Actions**: по расписанию запуски могут задерживаться на пару минут,
  а после 60 дней без активности в репозитории GitHub отключает расписание
  (любой коммит/страница запуска — и снова включается).
- Если новостей очень много и за 15 минут их больше, чем помещается на 2 первых
  страницы ленты, увеличьте: `--pages 3` в команде запуска (в `news.yml`).
- Контакт может в любой момент заблокировать бота — тогда сообщения перестанут
  приходить (в логах Actions будет видно ошибку).
